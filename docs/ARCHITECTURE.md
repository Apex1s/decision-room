# Architecture

Three kinds of process, three protocols, and one rule: **the language model never computes a number.**

```
 ACP client (Zed, JetBrains, cli.ts, web.ts)          MCP client (Claude Code, Claude Desktop, agents)
        │  ACP v1: JSON-RPC 2.0 over stdio                    │  MCP over stdio
        ▼                                                      ▼
 ACP agent: agent/src/main.ts                          MCP server: agent/src/mcp.ts
   one Room per session, persisted by store.ts           13 tools + methodology resource
        │                                                      │
        └──────────────  JSON-RPC 2.0 over stdio + progress notifications  ──────────────┘
                                         ▼
                 Engine (Python): python -m decision_room serve
                 one stateful Workspace per session (snapshot after each turn)
```

## ACP and MCP, each for what it is for

**ACP** standardises how an editor talks to *the agent you are working with*: sessions, prompts, streamed updates, tool calls, permissions, modes, slash commands and session management. It gives Decision Room its product experience inside Zed, JetBrains and any other ACP client:
- a plan you can follow;
- each specialist's work as an inspectable tool call with its chart;
- a permission prompt before files change;
- the memo as a diff;
- rooms you can close and reopen.

**MCP** standardises how an agent calls *tools*. Exposing the same specialists over MCP means a general agent such as Claude Code can call `recommend_prices` or `what_if` in the middle of its own work. The engine, the numbers and the red team are the same either way.

## ACP surface used

| ACP feature | How Decision Room uses it |
|---|---|
| `initialize` | `agentInfo`; `loadSession: true`; `sessionCapabilities.list` and `.delete`; `promptCapabilities.embeddedContext` |
| `session/new` → `modes` | **Advisor** (asks before writing files) and **Autopilot** |
| `available_commands_update` | 16 slash commands (`/brief`, `/recommend robust`, `/conduct`, `/whatif`, `/rule`, `/stress`, `/redteam`, `/memo`, …) |
| `session/prompt` | Plain English or slash commands; `resource_link` / `resource` blocks pointing at a CSV folder load that market |
| `plan` updates | One entry per specialist step, statuses updated live |
| `tool_call` / `tool_call_update` | Each specialist step is a tool call (`kind`: read, execute, think, edit) with streamed engine progress; finished calls attach their chart as an embedded `image/svg+xml` resource |
| `session/request_permission` | Before writing the memo in Advisor mode; "always" switches to Autopilot (`current_mode_update`) |
| `diff` tool-call content | The memo is shown as a new-file diff with its location |
| `session/cancel` | Stops between specialist steps; the turn ends with `cancelled` |
| `session/set_mode` | Switch Advisor / Autopilot from the client |
| `session/list` | Rooms for a working directory, titled after their first question |
| `session/load` | Replays the full conversation (`user_message_chunk` and every recorded update) before answering, and restores the engine's workspace snapshot so nothing is recomputed |
| `session/delete` | Removes the room and its snapshot |

## Agent (agent/src)

| File | Role |
|---|---|
| `main.ts` | ACP wiring with the official `@agentclientprotocol/sdk` (v2.1, protocol v1), including session persistence |
| `store.ts` | Session store (`~/.decision-room/sessions/<id>/`: metadata, history, engine snapshot); `DECISION_ROOM_HOME` overrides the location |
| `room.ts` | Expands actions into specialist steps; streams plan, tool calls, charts and results; writes the closing summary |
| `intent.ts` | Deterministic parser: slash commands and plain English → actions (firms and regions from the loaded market) |
| `llm.ts` | Optional Claude: routes free-form questions to the same action schema; writes a 3–5 sentence summary from engine JSON only |
| `mcp.ts` | MCP server (official `@modelcontextprotocol/sdk`): the specialists as tools, methodology as a resource |
| `engine.ts` | Spawns the Python engine, JSON-RPC client, progress callbacks, crash reporting |
| `render.ts` | Engine JSON → Markdown tables (shared by ACP and MCP) |
| `cli.ts` | Terminal ACP client (interactive, one-shot, scripted demo) |
| `web.ts` + `web/index.html` | Browser ACP client: a Bun server holds the ACP connection and relays it over WebSocket; rooms panel, inline charts |

## Engine (engine/decision_room)

| File | Role |
|---|---|
| `market.py` | Market model and CSV format (five files + optional capacity by period) |
| `synth.py` | Synthetic oligopoly with known parameters (nested logit, σ = 0.45); prices generated by the equilibrium, so they are endogenous |
| `demand.py` | Berry inversion, OLS vs 2SLS, plain vs nested logit, clustered SEs |
| `forecast.py` | Out-of-sample equilibrium forecast (prices and shares) vs naive, by calibration window |
| `equilibrium.py` | Nested-logit shares and derivatives; ζ-markup fixed point with capacity shadow prices; KKT certificate; uniqueness; implied costs under any conduct |
| `strategy.py` | Scenarios; Stackelberg leader (regional shifts over competitive grade markups); robust SAA optimisation; rule pricing; frontier |
| `risk.py` | Sampled worlds; Monte Carlo on the decision; what-if with and without reaction |
| `redteam.py` | 13 checks including the conduct test; mechanical grade; stated limits |
| `memo.py`, `charts.py` | Markdown and HTML memo; dependency-free SVG charts (light and dark) |
| `workspace.py` | Stateful session: one method per specialist, model selection, caching, snapshot/restore |
| `server.py` | JSON-RPC 2.0 over stdio; stdout is protocol only, logs go to stderr |

## Design choices

- **Two languages, each where it is strongest.** TypeScript for the protocols: the reference ACP and MCP SDKs, streaming, subprocesses, web. Python for the numerics: NumPy, SciPy.
- **Stateful engine per session, persisted.** A follow-up ("and if Dune expands?") reuses the fitted demand model and equilibrium, even after the editor has been closed and the room reopened.
- **Validate what you decide with.** Model selection and the out-of-sample test both forecast the equilibrium, not shares conditional on realised prices.
- **Offline by default.** The deterministic parser covers every command; Claude is an upgrade, not a dependency.
- **Fail loudly.** Engine errors become failed tool calls (ACP) or `isError` results (MCP); the red team can grade D, and the memo says so first.
- **Snapshots are private.** Engine snapshots are pickles written and read only by the agent itself, in the user's own session store; they are never loaded from user-supplied paths.
